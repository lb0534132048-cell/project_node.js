Express Router – מדריך למתחילים
מה זה Express Router?
Express Router הוא כמו תיקיית מיון לאפליקציה שלך. במקום לשים את כל הטיפול בנתיבים (routes) בקובץ אחד ענק, אתה מחלק אותם לקבצים נפרדים לפי נושא – כל נושא מקבל "ראוטר" משלו.

למה Router שימושי באפליקציות גדולות?
דמיין אפליקציה עם 100 נתיבים: ניהול משתמשים, קורסים, תשלומים, דוחות... בקובץ server.js אחד זה היה הופך לבלאגן של 3000 שורות. Router מאפשר:

בעיה	איך Router פותר
קובץ server.js ענק ובלתי קריא	כל תחום בקובץ נפרד תחת תיקיית routes/
קשה למצוא באגים	אתה יודע בדיוק באיזה קובץ לחפש
כמה מתכנתים עובדים במקביל	כל אחד עובד על קובץ ראוטר נפרד – בלי להתנגש
שימוש חוזר	אפשר לטעון את אותו ראוטר בכמה מקומות
הדוגמה הכי קטנה שאפשר
שלב 1: מבנה הפרויקט (רואים את זה גם בתמונות שלך)

const express = require('express');

// 2. יוצרים מופע של Router (לא app שלם – רק "מיני-אפליקציה")
const router = express.Router();

// 3. מגדירים נתיב פשוט – GET ל-/
router.get('/', (req, res) => {
  res.send('רשימת הקורסים');
});

// 4. מייצאים את הראוטר כדי להשתמש בו בשרת הראשי

הסבר שורה-שורה:

שורה 1: require('express') – טוען את ספריית Express. זה כמו לפתוח ארגז כלים.
שורה 2: express.Router() – במקום ליצור שרת שלם (express()), יוצרים רק "חתיכה" קטנה שמנהלת נתיבים. זה כמו לקחת מהארגז רק את כלי המיון.
שורה 3: router.get('/', ...) – כשיש בקשת GET לנתיב /, תפעיל את הפונקציה. בתוך הראוטר, הנתיב הוא יחסי. / כאן זה לא בהכרח / של כל האתר – נראה מיד.
שורה 4: module.exports = router – מייצא את הראוטר, כדי שקבצים אחרים יוכלו לטעון אותו.
שלב 3: חיבור לשרת – server.js
javascript
העתק קוד
const express = require('express');
const app = express();

// טוען את הראוטר של הקורסים
const coursesRouter = require('./routes/courses');

// מחבר את הראוטר תחת הקידומת /courses
app.use('/courses', coursesRouter);

app.listen(3000, () => {
  console.log('השרת רץ על פורט 3000');
});
מה זה app.use()?
app.use() הוא הפקודה הכי רב-תכליתית ב-Express. היא אומרת: "כל בקשה שנכנסת, תעביר אותה דרך הדבר הזה."

בהקשר של Router, השימוש הוא:

javascript
העתק קוד
app.use('/courses', coursesRouter);
מה זה אומר: כל בקשה שמתחילה ב-/courses – תשלח אותה ל-coursesRouter לטיפול. ה-coursesRouter יקבל את הבקשה אחרי שהורידו ממנה את הקידומת.

מה קורה כשבקשה מגיעה?
בוא נעקוב אחרי בקשת GET /courses/nodejs:

bash
העתק קוד
דפדפן  →  שרת (app)
                │
                ▼
         האם הנתיב מתחיל ב-/courses?  ✓ כן!

                ▼
         app.use('/courses', coursesRouter)

         הנתיב עכשיו: /nodejs
                │
                ▼
         router.get('/')?    הנתיב הוא /nodejs, לא /
         router.get('/nodejs')?   ✓ נמצא!
                │

הקידומת מתקלפת: app.use('/courses', router) מוריד את /courses לפני שהבקשה מגיעה לראוטר. לכן בתוך הראוטר כותבים router.get('/') וזה מתאים ל-/courses/, או router.get('/nodejs') שמתאים ל-/courses/nodejs.

טיפים חשובים
שמות קבצים ברבים: מקובל לקרוא לקבצים courses.js, students.js – מתאים לתוכן שהם מנהלים.
module.exports מול export default: בגלל שרוב פרויקטי Node.js משתמשים ב-CommonJS (שיטת require הוותיקה), מייצאים עם module.exports.
נתיב יחסי בתוך הראוטר: הנתיבים בראוטר תמיד יחסיים לנקודת החיבור. אם חיברת ב-app.use('/api/courses', router), אז router.get('/') יגיב רק ל-/api/courses/.

שכבת הנתונים (Data Layer) בפרויקט Express למתחילים
מה האחריות של שכבת הנתונים?
בפרויקט Express בלי מסד נתונים אמיתי, שכבת הנתונים היא המקום היחיד שמנהל את המידע עצמו. היא אחראית על:

אחסון – שמירת הנתונים בזיכרון (מערך, אובייקט) או בקובץ JSON.
קריאה – שליפת נתונים והחזרתם.
הוספה – יצירת רשומות חדשות.
עדכון ומחיקה – שינוי או הסרה של נתונים קיימים.
למשל, באפליקציית קורסים פשוטה:

javascript
העתק קוד
// data/courses.js — שכבת הנתונים

let courses = [
  { id: 1, name: 'מבוא ל-Node.js', hours: 40 },
  { id: 2, name: 'Express למתחילים', hours: 30 }
];

function getAll() {
  return courses;
}

function getById(id) {
  return courses.find(c => c.id === id);
}

function add(course) {
  const newCourse = { id: courses.length + 1, ...course };
  courses.push(newCourse);
  return newCourse;
}

module.exports = { getAll, getById, add };
האם ראוטים של Express צריכים להיכתב בתוך שכבת הנתונים?
ממש לא. וזו בדיוק הטעות שמתחילים נופלים בה.

הנה הסיבה, בשתי מילים: הפרדת אחריות.

שכבה	אחראית על	לא אמורה לדעת על
Routes (routes/courses.js)	לקבל בקשות HTTP, להחזיר תשובות	איך הנתונים מאוחסנים
Data Layer (data/courses.js)	לנהל את הנתונים עצמם	שיש בכלל HTTP, req, res
דוגמה לאיך זה נראה בפועל:

javascript
העתק קוד
// ❌ רע — ראוטר יושב בתוך שכבת הנתונים
// routes/courses.js
const express = require('express');
const router = express.Router();
let courses = [];  // ← הנתונים והראוטר מעורבבים באותו קובץ

router.get('/', (req, res) => {
  res.json(courses);  // ← הראוטר נוגע ישירות בנתונים
});
javascript
העתק קוד
// ✅ טוב — שכבת נתונים נפרדת
// data/courses.js
let courses = [];
function getAll() { return courses; }

// routes/courses.js
const coursesData = require('../data/courses');

router.get('/', (req, res) => {
  const courses = coursesData.getAll();  // ← הראוטר קורא לפונקציה, לא נוגע במערך
  res.json(courses);
});
למה ההפרדה הזו חשובה?
1. החלפת אחסון בלי לשבור כלום: היום הנתונים במערך, מחר ב-MongoDB. אתה משנה רק את data/courses.js. הראוטרים לא נגעו.

javascript
העתק קוד
// data/courses.js — במעבר ל-MongoDB, רק הקובץ הזה משתנה
const Course = require('../models/Course');

function getAll() {
  return Course.find();  // פעם הייתה מפה: return courses
}
2. בדיקות: אפשר לבדוק את שכבת הנתונים בלי להרים שרת HTTP. אפשר לבדוק את הראוטרים עם נתונים מדומים בלי לגעת באחסון האמיתי.

3. קריאות: כשמתכנת חדש נכנס לפרויקט, הוא רואה מיד — data/ זה נתונים, routes/ זה בקשות. הכל ברור.

סיכום
שכבת הנתונים היא המקום היחיד שנוגע בנתונים. הראוטרים מדברים רק איתה, דרך פונקציות, אף פעם לא ישירות. זה אולי נראה כמו "עוד קובץ" בפרויקט קטן, אבל ההרגל הזה חוסך כאבי ראש עצומים כשהפרויקט גדל.

שכבת השירות (Service Layer) באפליקציית Express
מה המטרה של שכבת השירות?
שכבת השירות יושבת בין הראוטר לשכבת הנתונים, והיא המקום שבו נמצאת הלוגיקה העסקית – כל החוקים, החישובים והבדיקות שהאפליקציה צריכה לבצע. היא דומה למנהל עבודה: הראוטר מקבל את הבקשה ומעביר אותה הלאה, ושכבת השירות היא זו שבאמת "חושבת" מה לעשות ואיך.

Controller באפליקציית Express
מה האחריות של Controller?
Controller הוא המתווך. הוא יושב בין הראוטר לשירות, ותפקידו היחיד הוא:

לקבל את req מהראוטר
לחלץ ממנו את מה שצריך – פרמטרים, גוף הבקשה, כותרות
לקרוא לפונקציה המתאימה בשכבת השירות
להחזיר תשובה ללקוח – res.json(), res.status(), וכו'
זהו. הוא לא חושב, לא מחשב, לא בודק לוגיקה. רק מקשר.

ההבדל בין Controller ל-Service
זו בדיוק אותה אנלוגיה של פונקציה סטטית שהזכרת קודם. ה-Service הוא לוגיקה טהורה – כמו פונקציה סטטית, בלי שום קשר לעולם שבחוץ. ה-Controller הוא הדבר היחיד שמכיר את עולם ה-HTTP ומתרגם אותו לקריאה ל-Service.

Controller	Service
מדבר HTTP – req, res	לא יודע מה זה HTTP
מחלץ נתונים מהבקשה	מקבל פרמטרים רגילים
קובע קוד סטטוס ו JSON	מחזיר ערך רגיל
אפס לוגיקה עסקית	כל הלוגיקה פה
יודע על קיום ה-Service	לא יודע שקיים Controller
דוגמה פשוטה
נניח אפליקציית קורסים. כשתלמיד נרשם, צריך לבדוק שהוא לא חורג ממכסת הקורסים. ככה זה נראה בשכבות:

javascript
העתק קוד

  if (!course) throw new Error('הקורס לא נמצא');

  const existing = enrollmentsData.getByStudent(studentId);

Controller בלי Service – הכל ביחד
javascript
העתק קוד
// controllers/enrollments.js
function enroll(req, res) {
  try {
    const course = coursesData.getById(req.body.courseId);
    const existing = enrollmentsData.getByStudent(req.params.studentId);

    // לוגיקה עסקית בתוך ה-controller
    if (!course) return res.status(404).json({ error: 'קורס לא נמצא' });
    if (existing.length >= 5) return res.status(400).json({ error: 'מקסימום 5' });
    if (existing.some(e => e.courseId === req.body.courseId))
      return res.status(400).json({ error: 'כבר רשום' });

    const result = enrollmentsData.add(req.params.studentId, req.body.courseId);
    res.status(201).json(result);
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
}

Express Router מול Controller – ההבדל
שניהם חלק מהאפליקציה, אבל באחריות שונה לחלוטין. הנה ההבדל המהותי:

Router שואל "לאיזה נתיב הבקשה הגיעה?" — ומנתב אותה ל-Controller הנכון.

Controller שואל "מה עושים עם הבקשה?" — ומחליט איך להגיב.

במילים אחרות: ה-Router הוא מפת דרכים. ה-Controller הוא נהג.

function getById(req, res) {
  const course = coursesService.getById(req.params.id);
  if (!course) return res.status(404).json({ error: 'לא נמצא' });
  res.json(course);
}

  const course = coursesService.create(req.body);
  res.status(201).json(course);
}

function update(req, res) {
  const course = coursesService.update(req.params.id, req.body);
  if (!course) return res.status(404).json({ error: 'לא נמצא' });
  res.json(course);
}

function remove(req, res) {
  const deleted = coursesService.remove(req.params.id);
  if (!deleted) return res.status(404).json({ error: 'לא נמצא' });
  res.status(204).send();

מהתמונות רואים שהיה לך קובץ routes/courses.js שבו הלוגיקה והנתיבים היו מעורבבים. הראוטרים המקוריים שלך נראו בערך כך (לפי מה שרואים בתמונות – קבצים שהשתנו, index.js שנמחק):

javascript
העתק קוד
// routes/courses.js – איך שהיה אצלך (בערך)
const express = require('express');
const router = express.Router();

// כנראה היה מערך courses כאן, או require ל-index.js
// והנתיבים הכילו גם את הלוגיקה עצמה
מה שיניתי
פירקתי את הקובץ הזה לשלוש שכבות נפרדות. כל שורת לוגיקה מצאה בית חדש:

מה היה ב-routes/courses.js	לאן זה עבר
מערך הקורסים ופונקציות CRUD	data/courses.js
בדיקות תקינות (האם יש name?)	services/courses.js
throw new Error כשאין קורס	services/courses.js
res.json(), res.status()	controllers/courses.js
router.get('/', ...), וכו'	נשאר ב-routes/courses.js – אבל בלי לוגיקה
איך נראה הראוטר עכשיו
javascript
העתק קוד
// routes/courses.js — החדש
const router = express.Router();
const coursesController = require('../controllers/courses');

router.get('/',     coursesController.getAll);   // היה: (req, res) => { ...לוגיקה... }
router.get('/:id',  coursesController.getById);  // אותו דבר, רק שהפונקציה עברה לקונטרולר
router.post('/',    coursesController.create);
router.put('/:id',  coursesController.update);
router.delete('/:id', coursesController.remove);
לפני: כל שורה שנייה בראוטר הייתה (req, res) => { עם לוגיקה בפנים.

אחרי: כל שורה בראוטר היא הפניה פשוטה: router.get('/', coursesController.getAll).

routes/students.js – אותו דבר בדיוק
בדיוק אותו טיפול. מה שהיה בקובץ הזה פורק לשלושה קבצים חדשים: data/students.js, services/students.js, controllers/students.js. הראוטר עצמו נהיה דק – רק טבלת הפניות.

server.js – השינוי היחיד
אצלך server.js כנראה הכיל את index.js (שנמחק, רואים את זה ב-git status). כנראה היה משהו כזה:

javascript
העתק קוד
// server.js — אצלך (לפני)
const express = require('express');
const app = express();

app.use(express.json());

// כנראה היה require ל-index.js שהכיל נתונים
// או שהראוטרים טענו משם משהו
שיניתי ל:

javascript
העתק קוד
// server.js — החדש
app.use('/courses', require('./routes/courses'));
app.use('/students', require('./routes/students'));
מה השתנה: הורדתי תלות ב-index.js (שנמחק אצלך), והשארתי רק את החיבור לראוטרים. עכשיו server.js אפילו לא יודע שקיימים controllers, services, או data. מבחינתו יש רק ראוטרים.

index.js – נמחק
מ-git status שלך רואים:

makefile
העתק קוד
deleted:    index.js
אצלך כנראה היה קובץ index.js שהכיל את הנתונים עצמם (המערכים של קורסים וסטודנטים). מחקת אותו – וזה בסדר גמור. אצלי הנתונים עברו לקבצים ייעודיים בתיקיית data/, במקום לשבת בקובץ בודד בשם index.js.

הקבצים החדשים שיצרתי – data/, services/, controllers/
אלו לא היו קיימים אצלך בכלל. יצרתי אותם מאפס, כשהתוכן נלקח מהלוגיקה שהייתה מפוזרת אצלך בתוך הראוטרים.

מה הולך לאן – טבלת סיכום
הקובץ החדש	מה יש בו	מאיפה הגיע התוכן
data/courses.js	מערך courses + פונקציות getAll, getById, create, update, remove	מה-index.js שנמחק + הלוגיקה הישירה שהייתה בראוטר
data/students.js	אותו דבר לסטודנטים	אותו מקור
services/courses.js	בדיקות תקינות + throw new Error	הלוגיקה שהייתה בתוך הפונקציות בראוטר
services/students.js	אותו דבר לסטודנטים	אותו מקור
controllers/courses.js	req.params, req.body, res.json, res.status, try/catch	כל השורות שקשורות ל-req ו-res שהיו בראוטר
controllers/students.js	אותו דבר לסטודנטים	אותו מקור
למה עשיתי את זה דווקא ככה
הפירוק נעשה לפי עיקרון אחד פשוט: כל פונקציה עברה למקום שבו היא עוסקת רק בדבר אחד.

שורה שנוגעת במערך (courses.push(...)) ← data/
שורה שבודקת תקינות (if (!name)) ← services/
שורה שנוגעת ב-req או res ← controllers/
שורה של router.get(...) ← נשארה ב-routes/
שום לוגיקה לא שוכפלה, שום דבר לא אבד. רק התארגנות מחדש.
