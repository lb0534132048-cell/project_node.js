למה שרת API צריך להחזיר קודי HTTP שונים – ולא תמיד 200
קודי HTTP הם הדרך התקנית של HTTP לתקשר מה קרה לבקשה – לא רק שהבקשה הגיעה. כשאתה מחזיר תמיד 200 OK עם גוף JSON שמכיל "error": true, אתה בעצם שובר את החוזה של הפרוטוקול.

בוא נפרק את ארבעת הקודים שביקשת להתמקד בהם:

200 OK – "הבקשה הצליחה"
200 אומר: הלקוח ביקש משהו, והשרת ביצע אותו בהצלחה.

מתי:

בקשת GET הצליחה – מחזירים את הנתונים.
בקשת PUT/PATCH עדכנה משאב קיים.
בקשת DELETE מחקה משאב.
למה לא להחזיר 200 על הכל?
אם תחזיר 200 גם על שגיאת התחברות, ספריות צד-לקוח (כמו Axios, Fetch, או כל HTTP client) יחשבו שהכל בסדר – לא יכנסו לבלוק ה-catch, לא יריצו middleware של טיפול בשגיאות, והקוד שלך יהפוך למלא ב-if (response.data.error).

201 Created – "נוצר משאב חדש"
201 שונה מ-200 במטרה מדויקת: לומר ללקוח שנוצר משאב חדש בעקבות הבקשה – בדרך כלל אחרי POST.

מה מיוחד בו:

הוא מאותת שהבקשה לא רק "הצליחה" – אלא שמשהו חדש נוצר במערכת.
נהוג לצרף כותרת Location שמכילה את ה-URL של המשאב החדש.
דוגמה משרת Node.js:

javascript
העתק קוד
app.post('/api/courses', async (req, res) => {
  const newCourse = await db.createCourse(req.body);
  res.status(201)
     .location(`/api/courses/${newCourse.id}`)
     .json(newCourse);
});
בלי 201, הלקוח לא יודע להבחין בין "עדכנתי משאב קיים" לבין "נוצר משאב חדש". זה משמעותי במיוחד כשהלקוח צריך לנווט לעמוד של המשאב החדש.

401 Unauthorized – "אינך מזוהה"
401 אומר: ניסית לגשת למשאב שדורש הזדהות, אבל לא סיפקת פרטי זיהוי תקפים (או בכלל).

מתי:

חסר טוקן JWT בכותרת Authorization.
הטוקן פג תוקף.
הטוקן לא תקף (חתימה שגויה, שונה).
שימו לב – 401 ≠ 403:

401 = "אתה לא מחובר / הטוקן שלך לא תקין. לך תתחבר."
403 = "אתה מחובר, אבל אין לך הרשאה לדבר הזה."
דוגמה:

javascript
העתק קוד
// middleware
function authenticate(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  
  if (!token) {
    return res.status(401).json({ message: 'נדרש טוקן גישה' });
  }
  
  try {
    req.user = jwt.verify(token, process.env.JWT_SECRET);
    next();
  } catch {
    return res.status(401).json({ message: 'טוקן לא תקף או פג תוקף' });
  }
}
אם תחזיר כאן 200, הלקוח יחשוב שהכל בסדר וינסה לעבד מידע שלא קיים – במקום להפנות את המשתמש למסך התחברות.

404 Not Found – "המשאב לא קיים"
404 אומר: הנתיב או המשאב שביקשת לא נמצא בשרת. זה יכול להיות:

נתיב לא קיים – GET /api/coursess (שגיאת הקלדה)
מזהה משאב שלא קיים – GET /api/courses/999 כשאין קורס 999
למה לא 200?
אם תחזיר 200 OK על משאב שלא נמצא – הלקוח לא יוכל להבחין בין "אין תוצאות" לבין "הבקשה נכשלה". דפדפנים, מטמונים, ו-proxy מקבלים החלטות על סמך קודי סטטוס. 404 אומר להם "אל תשמרו את זה במטמון בטעות".

דוגמה:

javascript
העתק קוד
app.get('/api/courses/:id', async (req, res) => {
  const course = await db.findCourse(req.params.id);
  
  if (!course) {
    return res.status(404).json({ message: 'הקורס לא נמצא' });
  }
  
  res.json(course);
});

מהם HTTP Request Headers?
כותרות בקשה (Request Headers) הן מטא-דאטה – מידע על הבקשה עצמה, לא על התוכן שלה. הן נשלחות אוטומטית על ידי הדפדפן או על ידי כלים כמו Postman, והשרת קורא אותן לפני שהוא ניגש לגוף הבקשה.

אם הגוף (body) של הבקשה הוא המכתב, הכותרות הן המעטפה – מי השולח, איזה סוג תוכן יש בפנים, באיזו שפה, ועוד.

דוגמאות נפוצות
כותרת	תפקיד
Content-Type	אומר לשרת מה יש בגוף: application/json, text/html
Accept	אומר לשרת איזה פורמט הלקוח רוצה בחזרה
Accept-Language	השפה שהלקוח מעדיף (he, en)
User-Agent	מזהה את הדפדפן או הלקוח
Host	לאיזה דומיין הבקשה מיועדת
למה שרת בודק כותרות לפני עיבוד בקשה?
השרת קורא כותרות לפני שהוא נוגע בגוף הבקשה – וזה חוסך עבודה מיותרת.

דמייני את זה כך: הדוור מגיע עם חבילה. לפני שהוא בכלל פותח אותה, הוא מסתכל על המעטפה. אם כתוב "דואר רשום" – הוא מטפל בזה אחרת. אם חסרה כתובת – הוא מחזיר אותה מיד, בלי לפתוח.

באותו אופן, שרת Express בודק כותרות כדי:

לסרב מוקדם: אם חסרה כותרת קריטית – אין טעם לקרוא את req.body בכלל.
להחליט איך לפרש את הגוף: Content-Type: application/json אומר לשרת לקרוא JSON. בלי זה – השרת לא יודע.
לנתב לטיפול שונה: למשל, גרסת API (Accept-Version: v2).
HTTP 401 Unauthorized
401 אומר: "אינך מזוהה. הבקשה שלך חסרה פרט זיהוי הכרחי."

זה שונה מ-403 Forbidden:

401 = אתה לא מחובר / לא סיפקת מפתח. לך תזדהה.
403 = אתה מחובר, אבל אין לך הרשאה לדבר הספציפי הזה.
דוגמה פשוטה ב-Express – בדיקת כותרת מותאמת
נניח שהאפליקציה דורשת כותרת x-api-key בכל בקשה – מחרוזת פשוטה שמייצגת מפתח גישה. בלי JWT, בלי ספריות חיצוניות.

Middleware שבודק את הכותרת
javascript
העתק קוד
// middleware/apiKey.js

// מפתח קבוע – בפרויקט אמיתי זה מגיע ממשתנה סביבה
const VALID_KEY = 'abc-123-secret';

function requireApiKey(req, res, next) {
  const apiKey = req.headers['x-api-key'];

  if (!apiKey) {
    return res.status(401).json({ error: 'חסרה כותרת x-api-key' });
  }

  if (apiKey !== VALID_KEY) {
    return res.status(401).json({ error: 'x-api-key לא תקף' });
  }

  // המפתח תקין – ממשיכים לבקשה
  next();
}

module.exports = requireApiKey;
חיבור לשרת
javascript
העתק קוד
// server.js

// middleware גלובלי – כל בקשה עוברת דרכו

app.use('/courses', require('./routes/courses'));

app.listen(3000);

למה לבדוק כותרת לפני עיבוד?
שימי לב: ה-middleware רץ לפני שהראוטר והקונטרולר בכלל מתעוררים. אם המפתח לא תקף, הבקשה נדחית בשלב הכי מוקדם – בלי לקרוא נתונים, בלי להריץ לוגיקה, בלי לבזבז משאבים.

זו בדיוק הסיבה ששרתים בודקים כותרות לפני עיבוד – לחסוך עבודה על בקשות שלא יטופלו ממילא.

HTTP Headers – הסבר מלא
מה זה HTTP Header?
HTTP Header (כותרת HTTP) זה מידע נלווה שהדפדפן או Postman שולחים יחד עם כל בקשה לשרת. זה לא התוכן של הבקשה עצמה – זה מידע על הבקשה. כמו המעטפה של מכתב: היא לא המכתב עצמו, אבל היא אומרת מי השולח, מה יש בפנים, ולאן זה צריך ללכת.

ב-Express, כל הכותרות שיושבות ב-req.headers – אובייקט שמכיל את כולן.

למה חשוב לאמת קריאות ומשתמשים?
כי שרת פתוח לכל אחד באינטרנט. בלי אימות:

כל אחד יכול למחוק קורסים
כל אחד יכול לראות מידע של משתמשים
אפשר להציף את השרת בבקשות
אימות בודק: מי אתה, והאם מותר לך לעשות את מה שאתה מבקש?

איזה סטטוס חוזר בקריאה לא מאומתת?
401 Unauthorized – "אינך מזוהה, לא סיפקת פרטי זיהוי."

לפעמים גם 403 Forbidden – כשהמשתמש מזוהה אבל אין לו הרשאה ספציפית.

קוד	מתי	דוגמה
401	חסר פרט זיהוי, או לא תקף	אין טוקן, מפתח API שגוי
403	מזוהה אבל חסרה הרשאה	תלמיד מנסה למחוק קורס שרק מנהל יכול
איך בודקים HTTP Headers בצד השרת?
ב-Express, req.headers הוא אובייקט רגיל. כל כותרת נגישה כשם מפתח באובייקט, באותיות קטנות:

javascript
העתק קוד

דוגמה מלאה: middleware לאימות
ניצור middleware שיבדוק כותרת x-api-key בכל בקשה, ויחזיר 401 אם היא חסרה או שגויה:

javascript
העתק קוד
// middleware/auth.js

// המפתח הסודי – בפרויקט אמיתי זה מגיע מ-env
const API_KEY = 'my-secret-key-123';

function checkApiKey(req, res, next) {
  // 1. שולפים את הכותרת
  const apiKey = req.headers['x-api-key'];

  // 2. אם חסרה – 401
  if (!apiKey) {
    return res.status(401).json({ error: 'חסר x-api-key. גישה נדחתה.' });
  }

  // 3. אם לא תואמת – 401
  if (apiKey !== API_KEY) {
    return res.status(401).json({ error: 'x-api-key שגוי. גישה נדחתה.' });
  }

  // 4. הכותרת תקינה – ממשיכים
  next();
}

module.exports = checkApiKey;

Middleware ב-Express – הסבר למתחילים
מה זה Middleware?
Middleware זו פונקציה שרצה בין הבקשה לתשובה. היא יושבת בשרשרת העיבוד – לפני שהבקשה מגיעה לראוטר ולקונטרולר.

תחשבי על זה כמו מאבטח בכניסה לבניין: לפני שאתה נכנס פנימה, עוצרים אותך, בודקים תעודה, ואם הכל בסדר – ממשיכים. אם לא – עוצרים אותך בדלת.

lua
העתק קוד
בקשה ← Middleware ← ראוטר ← Controller
          ↑
    בודק, מאמת, ומחליט:
    להמשיך (next) או לעצור (res.status)
מה עושה next()
next() היא פונקציה שאומרת ל-Express: "סיימתי, תעביר את הבקשה הלאה." בלי next() הבקשה תיתקע – היא לא תגיע לראוטר, והלקוח לא יקבל תשובה עד שהבקשה תיפסק בזמן קצוב (timeout).

כל Middleware מקבל שלושה פרמטרים: req, res, next. הוא יכול לעשות שני דברים:

לקרוא ל-next() → "הכל בסדר, תמשיך"
להחזיר res.status(...).json(...) → "עצור כאן, זו התשובה"
דוגמה: Middleware לאימות x-api-key
ניצור middleware שבודק שבכל בקשה נשלחת כותרת x-api-key עם ערך תקין. נפרק כל שורה:

javascript
העתק קוד
// middleware/auth.js

// שלב 1: מגדירים את המפתח הסודי
const API_KEY = 'my-secret-key-123';

// שלב 2: middleware מקבל req, res, next
function checkApiKey(req, res, next) {

  // שלב 3: שולפים את הכותרת מהבקשה
  const apiKey = req.headers['x-api-key'];

  // שלב 4: בודקים אם הכותרת חסרה
  if (!apiKey) {
    return res.status(401).json({ error: 'חסר x-api-key' });
  }

  // שלב 5: בודקים אם הערך שגוי
  if (apiKey !== API_KEY) {
    return res.status(401).json({ error: 'x-api-key שגוי' });
  }

  // שלב 6: הכל תקין – ממשיכים
  next();
}

module.exports = checkApiKey;
פירוק שורה-שורה – מה קורה פה
שורה	הסבר
const API_KEY = 'my-secret-key-123'	המפתח התקין. באפליקציה אמיתית – זה יבוא ממשתנה סביבה (process.env).
function checkApiKey(req, res, next)	Middleware הוא פונקציה רגילה שמקבלת req (הבקשה), res (התשובה), ו-next (הפונקציה שמעבירה הלאה).
req.headers['x-api-key']	כל הכותרות שיושבות ב-req.headers. x-api-key זו כותרת מותאמת – לא סטנדרטית, אנחנו המצאנו אותה.
if (!apiKey)	אם הכותרת חסרה לגמרי – undefined – נעצור כאן.
return res.status(401).json(...)	שולחים תשובה ללקוח: קוד 401 (לא מזוהה) + הודעת JSON. ה-return מוודא שלא ימשיך בטעות ל-next().
if (apiKey !== API_KEY)	הכותרת קיימת, אבל הערך שגוי.
next()	המפתח תקין – מעבירים את הבקשה הלאה. הראוטר והקונטרולר יתעוררו עכשיו.

העתק קוד
// ============================================================
// Middleware: אימות מפתח API
// פונקציה שרצה על כל בקשה, בודקת את הכותרת auth-key,
// ומחליטה אם להמשיך או לעצור עם 401
// ============================================================

// המפתח הסודי – נשווה כל בקשה מולו
const AUTH_KEY = 'my-secret-key-123';

function validateAuth(req, res, next) {
  // ==========================================================
  // שלב 1: תיעוד – מדפיסים כל בקשה שעוברת דרכנו
  // ==========================================================
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);

  // ==========================================================
  // שלב 2: שולפים את הכותרת auth-key מהבקשה
  // req.headers הוא אובייקט עם כל הכותרות
  // ==========================================================
  const authKey = req.headers['auth-key'];

  // ==========================================================
  // שלב 3: בדיקה – האם הכותרת חסרה?
  // ==========================================================
  if (!authKey) {
    // מדפיסים ללוג – מי ניסה לגשת בלי מפתח
    console.log(`גישה נדחתה – חסר auth-key`);
    // מחזירים 401 – הלקוח לא מזוהה
    return res.status(401).json({ error: 'חסרה כותרת auth-key. גישה נדחתה.' });
  }

  // ==========================================================
  // שלב 4: בדיקה – האם הערך תואם?
  // ==========================================================
  if (authKey !== AUTH_KEY) {
    // המפתח קיים אבל שגוי
    console.log(`גישה נדחתה – auth-key שגוי`);
    return res.status(401).json({ error: 'auth-key שגוי. גישה נדחתה.' });
  }

  // ==========================================================
  // שלב 5: הכל תקין – מעבירים הלאה
  // next() אומר ל-Express: "סיימתי, תמשיך לראוטר"
  // ==========================================================
  console.log(`אושר – ממשיך לטיפול`);
  next();
}

module.exports = validateAuth;

// ============================================================
// שכבת הנתונים – קורסים
// אחראית על האחסון בלבד. מקבלת נתונים, מחזירה נתונים.

// מערך שמדמה בסיס נתונים בזיכרון
const courses = [
  { id: 1, name: 'nodejs', hours: 40 },
  { id: 2, name: 'python', hours: 30 },
  { id: 3, name: 'react', hours: 35 }
];

// החזרת כל הקורסים
function getAll() {
  return courses;
}

// חיפוש קורס לפי id – מחזיר את הקורס או null אם לא קיים
function getById(id) {
  return courses.find(c => c.id === id) || null;
}

// יצירת קורס חדש – מוסיף id אוטומטי
function create(course) {
  const newCourse = { id: courses.length + 1, ...course };
  courses.push(newCourse);
  return newCourse;
}

// עדכון קורס קיים – מחזיר את הקורס המעודכן או null
function update(id, data) {
  const course = courses.find(c => c.id === id);
  if (!course) return null;             // לא נמצא – מחזירים null
  Object.assign(course, data);          // מעדכנים את השדות
  return course;
}

// מחיקת קורס – מחזיר true אם נמחק, false אם לא נמצא
function remove(id) {
  const index = courses.findIndex(c => c.id === id);
  if (index === -1) return false;       // לא נמצא
  courses.splice(index, 1);            // מוחקים מהמערך
  return true;
}

module.exports = { getAll, getById, create, update, remove };

// ============================================================
// קונטרולר – קורסים
// מתרגם HTTP ←→ Service.
// מחלץ נתונים מ-req, קורא ל-Service, מחזיר res.
// ============================================================

const coursesService = require('../services/courses');

// GET /courses – החזרת כל הקורסים
function getAll(req, res) {
  const courses = coursesService.getAll();   // קורא ל-service
  res.status(200).json(courses);             // 200 + הגוף
}

// ==========================================================
// GET /courses/:id – קבלת קורס בודד
// ==========================================================
function getById(req, res) {
  try {
    const id = Number(req.params.id);         // המרה למספר
    const course = coursesService.getById(id);
    res.status(200).json(course);             // 200 – נמצא
  } catch (err) {
    // הקורס לא נמצא – 404
    if (err.message === 'COURSE_NOT_FOUND') {
      return res.status(404).json({ error: 'הקורס לא נמצא' });
    }
    // שגיאה לא צפויה – 500
    res.status(500).json({ error: err.message });
  }
}

// POST /courses – יצירת קורס
function create(req, res) {
  try {
    const course = coursesService.create(req.body);
    res.status(201).json(course);             // 201 – נוצר
  } catch (err) {
    res.status(400).json({ error: err.message });  // 400 – שגיאת קלט
  }
}

// ==========================================================
// PUT /courses/:id – עדכון קורס בודד
// ==========================================================
function update(req, res) {
  try {
    const id = Number(req.params.id);
    const course = coursesService.update(id, req.body);
    res.status(200).json(course);             // 200 – עודכן
  } catch (err) {
    if (err.message === 'COURSE_NOT_FOUND') {
      return res.status(404).json({ error: 'הקורס לא נמצא' });
    }
    res.status(500).json({ error: err.message });
  }
}

// ==========================================================
// DELETE /courses/:id – מחיקת קורס בודד
// ==========================================================
function remove(req, res) {
  try {
    const id = Number(req.params.id);
    coursesService.remove(id);
    res.status(204).send();                   // 204 – נמחק, אין גוף
  } catch (err) {
    if (err.message === 'COURSE_NOT_FOUND') {
      return res.status(404).json({ error: 'הקורס לא נמצא' });
    }
    res.status(500).json({ error: err.message });
  }
}

module.exports = { getAll, getById, create, update, remove };

// ==========================================================

// הפעלת השרת

  console.log(`השרת רץ על http://localhost:${PORT}`);
